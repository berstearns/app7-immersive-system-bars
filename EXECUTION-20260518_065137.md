### Edit-mode interaction

Implemented as **auto-exit**: entering expanded view while in edit mode silently calls `editorCancel()`. Rationale: expand mode is for distraction-free reading. Restoring chrome (tap [Restore]) leaves edit mode off; the user can re-enable it from Flags.

### D2.3 — persistent flags + bubble fix under Fill (commit `c25f765`)

Two follow-ups in one commit since both were cheap and tightly coupled:

**(a) Persistent flags in `FlagsScreen`** — two rows:
- "Expand: with distortion (Fill — covers whole screen)" — default ON
- "Expand: without distortion (Fit — letterboxed)" — default ON

Each gates whether its entry button appears in the reader overlay. If both are off, no expand entry buttons. Backed by `_expandFitEnabled` + `_expandFillEnabled` `StateFlow<Boolean>` in `LauncherViewModel`, persisted via `SettingsStore` keys `expand_fit_enabled` / `expand_fill_enabled`.

**(b) Bubble-overlay fix under `Fill`** — taps + overlays were using letterboxed coords even though the bitmap was stretched. Refactor:

- Replace `var imageFitRect by remember { mutableStateOf(ImageFitRect(0f, 0f, 1f, 1f)) }` with four raw state vars (`lastImgW`, `lastImgH`, `lastContainerW`, `lastContainerH`) + a `remember(...)`-keyed `val imageFitRect` computed from those plus `expandMode`.
- When `expandMode == Fill`: `imageFitRect = ImageFitRect(0f, 0f, containerW, containerH)` — full-stretch, no letterbox. Bubble normalized coords now map to the full container.
- When `Fit` (or `Off`): keep existing `ImageFitRect.compute(...)` (aspect-preserving).
- Key benefit: the rect recomputes when `expandMode` flips, without waiting for a layout-bounds change (since `contentScale` doesn't change the Image's bounds, only how the bitmap fills them).

## Lessons / notes

- **`tmux send-keys` race**: when relaunching gradle in a pane, the `cd` command must be sent *and confirmed* before the build command. Sending `cd <path> && ./gradlew run` in a single send-keys works, but follow up with `pwd` to confirm. Today's first attempts at relaunching landed in the wrong folder because the cd was implicit and the prompt re-display was misread as "we're in the new folder now."
- **`app7-latest` symlink dereferences**: `rsync -a app7-latest/ <dst>/` dereferences the symlink and pulls from the actual folder. Confirmed by checking the bootstrap commit tree.
- **Two-toggle vs. one-toggle decision**: spec captures the rationale. The next pass should not collapse them into a shared "immersive mode" — recorded explicitly so the lesson outlives this folder.
